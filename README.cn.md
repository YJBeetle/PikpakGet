# PikpakGet

[English](README.md) | 中文

PikpakGet 按顺序下载 PikPak 分享链接中的文件。它先把单个文件转存到账号网盘，下载并核对内容后清理云端副本，再处理下一个文件。这样可以下载总大小超过网盘可用空间的分享；**单个文件仍必须放得进当前账号的网盘**。

支持多个账号。一个账号的下行流量用完后，程序会记录时间并尝试下一个未被本机进程占用的账号；满 1 小时后该账号重新进入候选。下载任务本身仍然是顺序执行，不会同时用多个账号下载。

## 安装

需要 Python 3.10+ 和 macOS 或 Linux。默认单连接下载不需要额外依赖；使用 `--connections` 分段下载时需要 `curl`。

```bash
git clone https://github.com/YJBeetle/PikpakGet.git
cd PikpakGet
python3 -m pikpakget --help
# 或安装为命令：python3 -m pip install -e .
```

## 开始下载

```bash
# 登录一个或多个账号；会话保存到各自的账号目录，密码不落盘
python3 -m pikpakget --login first@example.com
python3 -m pikpakget --login second@example.com
python3 -m pikpakget --accounts

# 查看计划，然后下载
python3 -m pikpakget links.txt --dry-run --dest /path/to/library
python3 -m pikpakget links.txt --dest /path/to/library

# 多个链接文件按参数顺序、文件内行顺序处理
python3 -m pikpakget catalogue/嗷大喵.txt catalogue/FXX.txt --dest /path/to/library

# 直接传分享链接，可与链接文件混用
python3 -m pikpakget https://mypikpak.com/s/SHARE_ID --dest /path/to/library
```

`links.txt` 每行一个分享链接。空行和以 `#` 开头的行会跳过。用制表符在链接后面写文件夹名，可以指定它在本地的归档位置：

```text
https://mypikpak.com/s/SHARE_ID_1	电影
https://mypikpak.com/s/SHARE_ID_2	剧集
```

没有指定文件夹的链接，默认使用它所在 TXT 的文件名（不含扩展名）。例如 `拘束屋.txt` 中未填写 Tab 目录名的链接会保存到 `DIR/拘束屋/`。目录名优先级为：行内 Tab 后的名字、`--folder-map` 映射、显式 `--default-folder`、TXT 文件名。传入多个 TXT 时分别取各自文件名，不会沿用前一个 TXT 的目录。`--limit` 限制合并后的前 N 条链接。

位置参数也可以直接是分享链接，与链接文件按参数顺序合并处理，同样支持 `?password=` 和制表符附加目录名。直接链接没有 TXT 文件名可回退，目录名最后一级为固定默认 `未分组`。

链接可以带文件夹路径（`/s/<分享ID>/<文件夹ID>/…`）。这种链接只枚举并下载该文件夹内的内容，并把它当作根目录：文件夹自身名字不另加一层，更深的子文件夹层级保留。

本地会保留分享中的文件夹层级。例如系列目录是 `Series`、分享根目录是 `象人工作室`、里面还有 `未编号`，文件会保存到 `DIR/Series/象人工作室/未编号/`。根目录文件夹与子文件夹按同一规则处理：如果根目录同时有文件和文件夹，根目录文件直接放在 `DIR/Series/`，文件夹里的文件放进对应子目录。分享标题不会被当作文件夹名；空文件夹也会创建。程序不会搬移旧布局中的本地文件；旧路径与新路径不同时，会在新位置重新下载。

网盘转存使用 `Pack From Shared` 文件夹。下载启动时若该文件夹有剩余项目，程序会列出并询问是否清理；空间不足时也会再次询问。提示为 `[Y/n]`：直接回车或输入 `y`、`yes`（不区分大小写）会永久删除列出的全部项目，包括归属未知的内容；输入 `n`、其他文字或中断则保留。`-y` 跳过询问，等同于确认清理全部项目。没有交互终端且未传 `-y` 时保留内容。若待转存文件放不进网盘，且文件夹为空或清理后仍放不下，当前文件会记为失败。清理范围只限 `Pack From Shared`。

## 常用命令

| 命令 | 用途 |
|---|---|
| `python3 -m pikpakget --accounts` | 查看已登录账号及使用顺序 |
| `python3 -m pikpakget --logout --account NAME` | 删除指定账号的本地会话和设备 ID |
| `python3 -m pikpakget --whoami --account NAME` | 查看该账号的云盘用量和订阅到期日 |
| `python3 -m pikpakget links.txt --inventory` | 统计分享文件、总大小及放不进云盘的文件 |
| `python3 -m pikpakget links.txt --dry-run` | 枚举下载计划，不转存、下载或清理云端 |
| `python3 -m pikpakget --status` | 查看此下载目录的本地进度，账号被占用时也能运行 |
| `python3 -m pikpakget links.txt --verify` | 下载时用云端 hash 检查已有文件 |
| `python3 -m pikpakget links.txt --verify --dry-run` | 只读复核已有文件，不下载或改名 |
| `python3 -m pikpakget --doctor` | 检查目录、锁、会话及网盘状态 |

常用参数：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--dest DIR` | `~/Downloads/PikPak` | 本地下载库；系列目录下保留分享原有的文件夹层级 |
| `--set-config dest=DIR` | 未设置 | 记住默认下载库；`dest=` 清除设置 |
| `--account NAME` | 自动选择 | 只用指定账号；流量受限时等待 1 小时后重试，可填账号名称或 `--accounts` 显示的 ID |
| `--connections N` | `1` | 单文件连接数；大于 1 时使用 `curl` 分段下载 |
| `--max-files N` | 不限 | 限制本次处理的文件数；失败尝试也可能占用名额 |
| `--skip-ext EXT[,EXT…]` | 空 | 跳过后缀匹配的文件（不区分大小写、可带点，如 `txt,.nfo`）；不转存、不下载、不计入进度 |
| `--limit N` | 不限 | 本次只处理前 N 个链接 |
| `--repeat N` | `3` | 最多扫描 N 轮，包含第一轮；整轮没有完成文件时提前停止；0 表示只扫一轮 |
| `--gap SEC` | `20` | 文件之间的等待秒数 |
| `--no-delete` | 关闭 | 保留本次转存的云端副本；日后空间不足时会询问是否清理 |
| `--log -` | 写入日志文件 | 只输出到终端 |
| `-v` | 关闭 | 显示转存/校验/清理等阶段细节（debug 级） |
| `-y` | 关闭 | 跳过清理询问，删除 `Pack From Shared` 中全部项目，包括归属未知的内容 |
| `--skip-bad-lines` | 关闭 | 忽略无法解析的链接行 |

其他选项见 `python3 -m pikpakget --help`。

`--skip-ext` 在枚举时生效：`--dry-run`、`--inventory`、`--verify` 复核与正式下载都按过滤后的清单统计；被跳过的文件不占 `--max-files` 名额，也不影响链接完成判定。本地已有的同后缀文件不会被删除或改名。

下载时终端会原地显示单文件进度、已下载大小、近几秒速度和预计剩余时间，每秒刷新。速度反映近几秒的实时吞吐；剩余时间按近 1 分钟的平均速度估算，短暂波动不会让时间翻倍跳变。每个文件完成时汇总一行（耗时、均速、核对分片）；转存、校验、清理等阶段细节默认不输出，`-v` 显示；等待空间释放超过 30s 或超时才提示。输出重定向时改为约每 30 秒一条普通进度日志；终端模式下日志文件仍每 5 分钟写一条普通进度行；`--quiet` 隐藏进度条。日志文件不包含终端刷新控制符。

## 进度和账号

每个系列的进度、锁和日志在 `DIR/<系列>/.pikpakget/`。同一系列一次只允许一个下载进程写入；不同系列可以并行运行，但同一个账号仍由本机账号锁独占。进度文件中的本地路径相对系列目录保存，整个系列可搬到另一个下载根目录。账号资料保存在运行设备的 `~/.pikpakget/`：

```text
~/.pikpakget/
├── accounts.json                  # 账号名称和使用顺序
└── accounts/<账号ID>/
    ├── device_id                 # 该账号专用
    ├── session.json              # 登录令牌
    ├── lock                      # 本设备上的账号锁
    └── traffic_capped_at         # 最近一次明确触及下行流量上限的时间（如有）
```

账号 ID 来自服务端用户 ID 的哈希，同一账号重新登录会沿用自己的设备 ID。账号锁只在本机生效：多台设备同时使用同一账号或网盘文件夹，程序无法互相协调。

程序会保存已完成文件的记录，重跑同一命令可继续未完成部分。已完成的分享也会重新读取清单，以发现后来新增的文件。服务端明确返回下行流量上限时，当前账号会冷却 1 小时，程序尝试下一个可用账号；如果全部账号都在冷却，就等到最早到期的账号再试。1 小时只是重试间隔，不保证服务端流量届时已恢复；再次触及上限会重新计时。等待期间可按 Ctrl+C 退出。全部账号被其他进程锁住时仍会报告“没有可用账号”，会话失效或初始化失败也不会当作流量冷却。

## 文件校验与限制

下载先写入 `.part`，完成后尝试用分享提供的内容 hash 验证。这个 hash 的分块规则是从样本推断的；没有候选分块大小能匹配时，不等于字节一定损坏。程序会在重试用尽后把文件保留为 `.unverified`，不会把它当作已验证文件。

`.part` 和分段片段保存在目标文件旁边。有该文件的进度记录时，重跑会续传；如果 `.pikpakget` 丢失，或当前文件没有进度记录，程序处理到该文件时会删除对应的 `.part` 与分段片段，从头下载。不会扫描或清理其他文件的片段。

重新扫描分享时，已有文件默认按相对路径和精确大小识别，直接记为完成，不再转存或下载。这包括 `.pikpakget` 丢失后重新建立进度。这个快速判断无法发现内容不同但大小相同的文件；加 `--verify` 会用分享提供的 hash 检查已有文件，核对失败时保留原文件并以冲突后缀重新下载。已核对过的文件在 source_hash、大小、mtime 都未变时跳过重算，新下载并核对通过的文件会当场记下这两项缓存。云端没有 hash 时会提示，并按路径与大小判断。`--verify --dry-run` 只读扫描并报告缺失、大小或 hash 不符；不下载、不改名、不清理云端。新下载的文件仍按原有流程校验。旧的独立 `--verify` 复核模式已删除。

旧版 `DIR/.pikpakget/` 不会被读取或迁移。请自行移动已下载文件到对应系列目录；再次运行会按上述规则识别现有文件。

当前进度格式为 v5：系列内以分享 URL 作为任务标识，文件记录的 `link_key` 指向该任务，不再把系列名拼进标识。旧格式进度不会迁移，遇到时会报错；请自行移走旧 `state.json` 后重跑。已有正式文件可重新识别，无进度对应的下载片段会在处理到该文件时删除重下。

- 单个文件大于账号可用网盘空间时会跳过。
- `--connections 1` 是默认值；分段下载可能因服务端限速而更慢。
- 网盘 API、配额和风控行为可能变化。多账号轮换不能保证每个账号都能成功下载。
- 如果服务端返回 `PROHIBITED`（例如当前地区不支持分享），该链接无法枚举文件；程序会报错，不会把 0 个文件记为已完成。
- Windows 原生环境不支持所需的 POSIX 文件锁；可在 Linux、macOS 或 WSL 中运行。
- 测试覆盖本地逻辑和本地 HTTP 下载；多账号云端清理与切换尚未用真实账号完成端到端验证。

日志和进度文件包含分享链接、文件名及本地路径；会话文件包含可用的登录令牌。不要直接上传这些文件。详见 [SECURITY.md](SECURITY.md)。
